# Archive format v1 — development

`@daclify/modules/archive` currently exports bounded binary chunks, canonical manifest encoding/decoding, domain validation, Merkle-tree construction and proof verification. This is the format library for the implemented Archive service module hosted by core. It has no separate blockchain account. Export jobs, administrator approval, availability attestations, source pruning, billing and history UI are not implemented by this library.

The format binds each chunk to its format version, chain, runtime, DAO, source account, source code hash, raw ABI hash, source schema hash, table, scope, chunk ordinal and leaf count, in that order. Fixed integers use unsigned little-endian Antelope serialization. Names use packed uint64 values; checksums use 32 raw bytes. The domain occupies 178 bytes in version 1.

A chunk contains the packed domain followed by a varuint32 row count and ordered `(uint64 primary key, length-prefixed original row bytes)` records. It may contain 1–65,536 rows and must fit within 5 MiB including this encoding. Empty families produce no chunk. Duplicate or descending primary keys, noncanonical variable-length integers and trailing bytes are rejected. The decoder bounds counts before allocating records.

The leaf is SHA256 of `0x00 || SHA256(domain bytes) || uint32 leaf index || uint64 primary key || varuint32 row length || original row bytes`. A parent is SHA256 of `0x01 || left hash || right hash`. An odd final node duplicates itself; proofs must supply that exact duplicate. Proof direction derives from the checked index, and path length derives from the leaf count, with at most 16 levels.

`decodeArchiveChunk` requires the expected domain and root from the approved descriptor. It returns the original packed bytes and does not accept a downloaded ABI. The eventual source decoder/planner must separately verify the released row schema, irreversible snapshot, complete coverage and pruning eligibility. A valid hash does not prove that a file remains available, that a source row is eligible for deletion, or that an administrator approved deletion.

Original ciphertext remains ciphertext. The formatter does not decrypt documents, transform key grants, or recover lost member keys. Manifests/provider labels must omit private titles, filenames and identities. Key grants, identities, treasury liabilities and payment replay protections remain live; the first planned pruning families are finalized ordinary-poll votes and unreferenced old document versions after manual approval and the eligibility delay.

Archived files remain pinned and count toward the same approved per-DAO storage capacity as active files. The approved commercial policy is 100 MB free plus $1 per additional approved 1 GB per month, in decimal units. Core implements configured prepaid subscriptions and verified CID accounting; live provider qualification and thirty-day cleanup remain pending; this library does not charge or unpin anything.

The independent fixture in `tests/fixtures/archive-v1.json` was calculated with Python `struct`/`hashlib`, including Antelope name and varuint packing. TypeScript and compiled C++ on the owned Spring/Telos-system fixture match its domain, leaves, root and proofs. Property tests use seed 20261008; boundary tests include the 5 MiB wire limit and 65,536 leaves. These results qualify the tested format, not a production Archive service.

## Canonical manifests and recovery verification

`createArchiveManifest` validates a complete descriptor body and computes its descriptor commitment. `encodeArchiveManifest` checks that commitment and encodes canonical UTF-8 JSON, at most 5 MiB. `decodeArchiveManifest` requires the SHA-256 commitment of those exact uploaded bytes, rejects invalid UTF-8/noncanonical JSON and validates domains, ordered families/chunks, counts and file-version references. The manifest contains no hash or CID of itself.

A manifest names one source deployment, its code and raw ABI hashes, the full DAO reference, block number/ID/time, table-specific schema hashes, covered families, ordered chunks/roots/CIDs/actual bytes/commitments/primary-key boundaries and retained original file references. The block number must match the first four block-ID bytes. This consistency check does not prove irreversibility or complete RPC coverage; the future coordinator must establish both from authoritative state. Families order by kind, numeric parent ID, table and numeric scope; chunks order by contiguous ordinal and ascending keys. Empty families have zero records and no chunks. Duplicate family coverage/chunk CIDs and incorrect counts are rejected.

`archiveDescriptorHash` packs version, DAO/source hashes, snapshot and the complete ordered family/chunk/file descriptor lists with Antelope integer/name/checksum/string/vector encodings. Core’s `archive_manifest_descriptor` uses the same field order. The Python standard-library fixture in `tests/fixtures/archive-manifest-v1.json` matches TypeScript and the actual compiled C++ native action, including the manifest byte commitment. The manifest hash and descriptor commitment must both be bound to future administrator approval and availability attestation.

`verifyArchiveChunkDescriptor` verifies one chunk’s exact byte length/commitment, domain, Merkle root and primary-key boundaries. `verifyArchiveChunks` additionally verifies complete bundle coverage and rejects duplicate original table/scope/primary keys. Its full-memory convenience path is capped at 64 MiB; larger recovery must use bounded per-chunk verification. These helpers preserve original packed bytes and do not accept an arbitrary downloaded ABI. Released schema selection, original-file retrieval, backup attestation, index restoration and source eligibility remain separate required checks. Neither helper declares original referenced files available merely because the manifest contains their CIDs.

## Schema decoding and host persistence

`archiveSourceSchema` exposes the code, binary ABI and schema hashes for the compiled vote/document models in this development packet. `decodeReleasedArchiveRow` accepts only those whitelisted models, validates source/scope, original primary key and parent ballot/document, rejects trailing/noncanonical row bytes and returns the original packed bytes alongside producer-typed values. Document ciphertext and key-epoch metadata stay unchanged. This is not a historic-release catalogue: retain and qualify older immutable schema packets before pruning or claiming upgrade-safe history recovery. Other record families remain opaque export data and are not decoded or pruned by this helper.

The Node host imports `ArchiveMigrations` from `@daclify/modules/archive/migrations`. Its URLs resolve to the SQL bytes included in the installed producer tarball. Core applies these under the separate `archive` namespace using its existing transaction, migration lock and immutable source-hash checks, after core migrations. The first migration creates resumable export/chunk records and freezes their request/source/snapshot/coverage domain and pinned manifest. It requires verification and backup/anchor metadata before advanced phases. SQL metadata and constraints do not establish provider availability or native pruning authority; the coordinator must prove both before acting. No export worker, approval route or pruning operation is enabled by applying this migration.

## Terminal markers and ordinary-poll planning

Decide keeps `pollends` in a parallel table without rewriting ballots or votes. A newly opened ordinary poll creates a fixed-size unfinished marker; finalizing it records the actual chain time. The module's native `markpoll` maintenance action can mark a previously finalized ordinary poll. Missing historic finalization time is never inferred from `closes`; its migration time starts a new 90-day wait. Repeated marking preserves the original completion/migration timestamp and ballot bytes. Elections, work execution and grant execution are excluded.

`planOrdinaryPollArchive` accepts producer-validated source/DAO/snapshot data, up to 64 selected ballots and 65,536 total vote rows. The host must read complete coverage and establish irreversibility; the library does not turn a supplied block ID into that proof. The planner rejects mismatched source hashes, code newer than the supplied snapshot, wrong DAO/parent, duplicate IDs/members, invalid weight/choices and incomplete vote/tally totals. Eligibility requires 90 days or a longer approved delay from a terminal marker present by the snapshot. Protected execution/election families and unfinished polls remain blocked.

Eligible rows retain canonical packed bytes and released schema/domain in bounded chunk plans. The reported RAM estimate is gross row/index bytes only; shared table headers, retained markers, future anchors and migration overhead are not deducted, so it is not a net savings claim. Empty vote families produce no chunks. Every output sets `pruningAuthorized: false`. Export storage reservations, independent recovery-tested backups, native approvals/anchors, safe ID allocation and source-owned pruning remain separate required gates. The old observer module can be reproduced locally with `npm exec -- tsx tools/build-upgrade.ts` to test the legacy marker upgrade. This is an unpublished development baseline, not a released historic-schema catalogue.

## Authenticated preview host

The core host exposes the producer-owned `POST /v1/archive/preview` route. It requires session/CSRF protection and a fresh check of active DAO administrator membership in the exact deployment. Previewing creates no export, payment or pruning approval. Requests select at most 64 ballot IDs and a delay of at least 90 days; the host reads at most 65,536 votes and rejects incomplete/nonadvancing pagination.

The native adapter pins the current core/source code and raw ABI, installed source identity and exact last irreversible block ID/number. It rejects source code newer than that block and checks the pins again after reading. `get_table_rows` reads head state; it does not accept an invented historical-block parameter. This limited preview relies on the reviewed source's immutable terminal polls/votes and the conservative terminal-age condition to relate the covered rows to the irreversible snapshot. It is not a general historical-state reader. Financial/election families remain protected, and complete vote weights/tallies are checked before eligible plans are returned.

Resources shows eligibility, the original delay, blocked reasons, snapshot and gross RAM estimate. Changing the selected ballot clears preview consent. Administrators may approve a resumable export using existing hosting capacity, create a verified independent encrypted backup, obtain a native anchor and sign exact approval or revocation. Each enabled ordinary-poll prune batch is explicit and source-owned. Preview or export alone never authorizes deletion. Production pruning remains off until allocation, migration, restore and provider gates pass.

## Resumable exports and standalone recovery

`archiveExportConsent` binds the full DAO/source and exact immutable selected row plans. It allows a newer irreversible snapshot but rejects changed source/coverage. The maximum stored-byte estimate includes complete encoded chunks and a canonical manifest with every CID reserved at its schema maximum length. It is a conservative reservation, not a new payment or net RAM saving.

Core implements the producer-owned export, list, refresh and bundle routes. Complete capacity is reserved under the same DAO lock used by documents. Each asset consumes its portion atomically, retaining unknown outcomes. SQL freezes request/source/snapshot/plan, upload request IDs and verified manifest domains. Work advances one chunk per reconciliation; the existing stoppable host loop runs the outbox. The original requesting administrator must remain active/authorized. No file or source row is deleted; unused reservation is released only after the verified manifest is saved.

The downloadable JSON contains canonical manifest bytes and packed ordinary-poll chunks. `verifyArchiveBundle(bundle, expectedManifestCommitment)` compares against a separately trusted expected commitment, validates complete coverage/current qualified source schemas and decodes original rows without a backend database. Its in-memory path is capped at 64 MiB. Core provides `npm run archive:verify -- /path/to/bundle.json <expected-manifest-sha256>`; keep that SHA-256 separately with your off-server backup. Native availability and signed approval are separate actions. Standalone verification authenticates only its independently supplied manifest commitment; use verifyAnchoredArchive with a reviewed native anchor for chain provenance.

This bundle does not contain vault/recovery/decryption keys, social pairings, original document files or a complete operator database. Original ciphertext and decryption keys remain separate recovery requirements. Retain the matching qualified decoder package before any future pruning or upgrade. SQL migration `002_transport.sql` extends the producer's export tables; core migration 025 owns the storage holds. Old migration hashes remain unchanged. See core [export operations](../../daclify-backend-core/docs/archive-exports.md).

## Independent backup receipts

The host's optional encrypted backup action binds the exact displayed manifest, export and DAO to an authenticated encrypted recovery bundle. Producer-owned `ArchiveBackupReceiptSchema`, backup route/status fields and immutable namespaced `003_backups.sql` preserve its file commitment and verification event. The core host verifies a complete independent restore before saving the receipt and rechecks administrator access. Backup bytes and their secret key stay outside public API status. The host can fall back from failed primary retrieval to the matching saved copy. Native availability attestation, approval and pruning remain separate; the operator must qualify the backup store's physical independence and durability. See the core export operations runbook for offline keys and database-free verification.

## Source binding and historical readers

All five modules expose owner-only `bindrampool` for physically allocated payer pools. A bound payer accepts writes for exactly one runtime; another runtime or rebind is rejected. Unbound modules retain independent-runtime support without funded pools. Do not bind an already shared module until other runtimes' work has been drained or migrated with authorization. This is not automatic quota enforcement or a completion guarantee.

The package retains trusted pre-pruning and pre-binding vote readers and the pre-pool document ABI/code identity. Code upgrades do not grant arbitrary downloaded ABIs decoder authority. The live/archive merger orders canonical vote IDs, deduplicates identical rows and rejects changed payloads for an existing ID or another parent. The host obtains irreversible-stable live rows without SQL and exposes when live coverage is unavailable. Original document ciphertext can be decoded from verified chunks and opened with recovered original keys/grants; original file blobs are separate. An owned native ordinary-vote database-loss drill plus original-kit recovery of a retained private file passed. Source-owned document pruning/selective restoration now have owned native qualification. Full RAM enforcement/legacy migration, live-provider qualification and production rollout remain release work.


## Referenced document versions

`DocumentArchiveRequestSchema` selects 1–25 source rows of one document. The producer-owned planner requires complete current-source reference coverage, exact native clocks/hashes and mature older versions. Latest/referenced versions are blocked. Poll requests preserve their existing wire shape. Document manifests derive file references from original rows and standalone verification checks exact file coverage, so an arbitrary CID does not become an owned pin or bill.

Works references immutable projects and current milestone submissions/reviews; Grants references rounds and current applications/decisions; Decide references immutable elections and recall documents; endorsement admission references current join applications. Frozen agreements/awards inherit their protected project/application rows. `backfillrefs` scans at most 25 primary rows, filters the exact DAO and commits code-bound progress only through its native source. Completing or retrying a scan does not rewrite source rows. Changed source code invalidates completeness. Disabled sources retain protection.

Archive migration 005 backfills manifest/chunk retention groups after the host creates its ledger in core migration 029. New exports and owned-pin recovery record complete groups in the same DAO scope. Pinning price and unique-CID accounting do not change. Original file blobs remain separate retention references and recovery requirements.

Core owns `prunedocs`, retained author/version/primary-key/hash metadata and `restoredoc`; the deployment plan links restoration to native `execctx`. History can decode exact original ciphertext without recreating RAM rows. Restoration validates the retained row hash and consumes normal capacity. No generic table erase, key-grant pruning or financial-state pruning is introduced. See [core archive operations](../../daclify-backend-core/docs/archive-exports.md) for migration recipes and actual native evidence.
